# Satellites on screen: CONFIG sats, SATS and LINK's shared view (2026-09-27)

For the link lane (1.2.0-link.7 plus the multi-board design in
`internal/link-multiboard-2026-09-27.md`). Three screens specified at 40
and 80 columns, with 132 where it changes anything, plus the words the
brief asked for. Nothing in `src/` was changed.

How it was measured: the `wt-link` host build (`host/bbs_host`,
1.2.0-link.7) run on 127.0.0.1:6871 with its own data directory, driven
over telnet by a script using `tools/testclient.py`, and the bytes
rendered to a grid with `render_lines` at 40 and 80. Captured: CONFIG,
CONFIG files, a file area's sub-page, CONFIG cameras, LINK and SYS, on
ANSI at 40 and 80 and on plain ASCII in line mode. Every mock-up below was
generated by a script that builds each line to the Form and row geometry
in `src/core/form.h` and `src/core/bbs_shell.cpp` and fails on any line
past the row width; none do, except the one block that shows today's
LINK running over on purpose.

## The verdict

The machinery is already right for this. CONFIG sats is a CONFIG form of
the same shape as CONFIG files, a button a satellite opening a page of its
own, and it fits the 16-field form with a field to spare in the worst case
(four other boards on one satellite). The work is in four small core gaps,
not in the layout: a CONFIG page whose values live in the link's peers
file rather than `system.cfg`, buttons that do something other than open a
sub-page, a question word for those buttons in plain ASCII, and camera
numbers that are fixed rather than list positions. SATS is a lookup table
and stays one column at every width; its staff detail is where 80 and 132
earn their width, as two and three groups side by side. LINK needs its
existing 40-column lines fixed before anything is added to it: one of them
is 41 characters today with every counter at zero.

## Decisions

- **CONFIG sats is a CONFIG form, not a list screen.** A row a satellite,
  each a button to a sub-page, then Pair, the two links and the channel.
  Same shape as CONFIG files and CONFIG forums, so a sysop already knows
  it, and plain ASCII gets it free as questions. A list-then-form screen
  would be the only list inside CONFIG and would need its own keys.
- **A satellite is known by its camera number everywhere a caller or the
  sysop's settings see it** (SATS, CONFIG sats, SNAPSHOT, CAMERA). LINK
  keeps the pairing number, because LINK is the radio and a door box has
  no camera number. LINK counts pairings from 1, as every other list on
  the board does.
- **Camera numbers are fixed, not positions.** "auto" takes the lowest
  free number from 2 (from 1 on a board built without a camera); a set
  number never moves when another satellite is paired or forgotten.
- **Satellite names are one word**, up to 16 characters, unique among the
  board's cameras ignoring case, because `SNAPSHOT name` takes one word
  and the first match.
- **SATS gets no shortcut.** `S` is free, and it is the one letter that
  says SATS, but SATS is read once to learn the numbers and SNAPSHOT is
  typed every time. If `S` is spent, spend it on SNAPSHOT. The table of
  taken letters is below.
- **SATS is a core verb beside SNAPSHOT and CAMERA** (`cameras.cpp`),
  there while a satellite is paired and gone with the last one. In the
  link plugin it would carry the link's read level, staff, and no caller
  could run it.
- **Staff get a one-screen summary from SATS and the whole of one
  satellite from `SATS n`.** Everything the brief lists for staff does not
  fit a row per satellite at 40, and 24 rows do not hold it as a block per
  satellite.
- **The busy answer breaks after its comma at 40**, into two lines that
  each read whole. markedLine's own wrap breaks it at "2 ahead / of you".
- **CONFIG's page list becomes two blocks**: core pages with their
  descriptions, then plugins. Adding `sats` and `camsat` takes today's
  single column to 26 lines at 40, and the title scrolls off a 24 or 25
  row screen.

## 1. CONFIG sats (sysop)

### The page

Title `SATELLITES`. Rows, in this order:

- One button a camera satellite, in camera-number order. Label `Camera n`
  (8 characters, at 40 and at 80). Button text:
  - 40: name in 12 (cut only past 12), a space, the state word in 10.
    Inside the button that is columns 14 to 36.
  - 80: name in 16, two spaces, state in 13, two spaces, sharing in 19.
    Columns 25 to 76.
  - State words: `awake`, `asleep`, `busy`, `no answer` at 40 and
    `not answering` at 80.
  - Sharing (80 only): `shared by 3, owner`, `shared by 2`, `not shared`.
- `Pair new` / `Pair a satellite`: leaves CONFIG and runs LINK PAIR's
  conversation, which already asks on the sysop's own screen.
- `Default` / `Default camera`: the value of CONFIG cameras' `camera` key
  as its text; opens CONFIG cameras, and Esc or Save there comes back here.
- `Settings` / `Satellite settings`: opens CONFIG camsat and comes back.
- `Channel` / `Wi-Fi channel`, read-only: `6, the router's`, and at 80
  `. A shared satellite needs one channel.` after it.

Field budget: at most 8 satellites (the board's 8 pairings, door boxes
included) plus 4 rows is 12 of 16. The form is then 19 rows of 23.

Status line with the focus on a satellite: `Enter: what it sends, share,
unpair` (35) at 40, `Enter opens this satellite: its name, number, what
it sends here, sharing.` (73) at 80. F1 on this page, where nothing is a
value: `Nothing to save: buttons open pages.` (36).

### The satellite's page

Title `CAMERA n: NAME`, capitals like every CONFIG title. Rows, in this
order; what this board sets first, then what it can only read, then what
it can do:

| # | 40 label | 80 label | Kind | Value |
|---|---|---|---|---|
| 1 | Name | Satellite name | text, 16 | one word |
| 2 | Camera no | Camera number | cycle | `auto`, `2` to `9` |
| 3 | Timelapse | Receive timelapse | yes/no | this board's choice |
| 4 | Motion | Receive motion | yes/no | this board's choice |
| 5 | Type | Type | read-only | `camera, OV2640` (80 adds `, up to UXGA`) |
| 6 | Status | Status | read-only | see the vocabulary below |
| 7 | Signal | Signal | read-only | word, dBm, rate |
| 8 | Owner | Owner | read-only | `this board` or the owner's name |
| 9-12 | Also on n | Also paired with n | button (owner) or read-only | each other board: name, heard |
| 13 | Share | Share with a board | button, owner only | opens its pairing for 2 minutes |
| 14 | Unpair | Unpair from here | button | forget it here, asks first |
| 15 | Settings | Camera settings | button (owner) or read-only | CONFIG camsat, or `set on <owner>` |

Budget: 15 fields at most (four other boards: the design's cap of 5 less
this one), so one to spare. The form is then 22 rows: fields on rows 4 to
18, the buttons on 20, the status line on 22.

Value rules, in columns:

- Read-only values take the box: 26 characters at 40, 55 at 80 (the box
  less one). Nothing on this page wraps.
- Status vocabulary, 40 / 80:
  - `awake, heard 4s ago` / `awake, heard 4 s ago, up 3 h 12 min`
  - `asleep since 14:30` / `asleep since 14:30; awake about 3.9 s a
    picture` (the awake time once measured; a battery figure goes here if
    a satellite ever reports one)
  - `busy, taking a picture`
  - `not answering since 14:05`
  - "asleep" is a satellite whose running settings (its SETTINGS_OK echo)
    say it deep-sleeps and that is not up; "not answering" is one that
    should be awake and is not.
- Signal: SYS's word for the dBm, then the figure. 40: `good, -58 dBm, 24
  Mbps`. 80: `good: -58 dBm here, -61 there, 24 Mbps`.
- Also on, 40, inside a 23-column button: name in 13, a space, `heard 1m`
  or `not heard`. 80: name in 16, two spaces, `heard 1 min ago` or `not
  heard since 14:05`, with `owner, ` first on the owner's row.
- Times: 40 uses LINK's `ago()` (`4s`, `1m`, `3h`); 80 spells the unit
  (`4 s ago`, `1 min ago`, `3 h ago`).

## 2. SATS

### Who sees what

- A caller sees a satellite when they may see its photos or take one
  (camsat's `photos` and `snap` levels), guests included where those say
  `all`. None visible: `No satellite here is open to you.`
- The staff view is for any staff level, SYS's rule. The rows that
  identify hardware (MAC, the key fingerprint, the other boards' names)
  also need the `NODES` permission, the one that shows caller addresses in
  LAST. Co-sysop 2 holds NODES by default, so by default every staff level
  sees everything, and a sysop who takes NODES from a level takes these
  with it.
- The caller view carries none of: MAC, channel, key or fingerprint, dBm
  or any signal figure, rate, other boards, firmware, pairing state. Its
  test checks by content: no `:`-separated hex pair, no four-hex-digit
  group, no `dBm`, no `ch `, no board name from PEERS.

default; 4 space; 5-20 name (16, the name's own cap, so never cut); 21

## What the core needs (hand-backs, not code)

- **A CONFIG page backed by the link, not by `system.cfg`.** `sats` in
  `kPages`, after `cameras` so no row above it moves, with `satellites` as
  an alias the way `wifi` is. Its rows are built at open from the link's
  pairings, and its sub-page reads and writes the peers file's name,
  `recv` and `camno` through `linkp::` calls, then sends SETTINGS byte 21.
  Composites cannot do it: they unpack and pack one `system.cfg` key.
  `g_cfgBuf` and `g_subBuf` hold the values; the new static state is the
  satellite being edited and the page to return to, a few bytes.
- **Four things a button can do; today it can do one.** Open a sub-page
  (exists). Go to another CONFIG page and come back on Esc or Save (new:
  a return page). Leave CONFIG and run a command (new: Pair runs LINK
  PAIR). Ask, then act in place (new: `Form::ask` for a button, not only
  for Save, with the pending row remembered).
- **A question word for a button in plain ASCII.** Line mode says `open
  (y/N)?` for every `FF_ACTION`. A button never uses `FormField::choices`,
  so a non-null `choices` on an action field can be its word (`revoke`,
  `share`, `unpair`) at no cost. FormField has no free flag bit (1 to 128
  are all taken), and a new pointer is 4 bytes x 16 fields x 12 sessions.
- **Button text built for the terminal**: padded columns for ANSI and
  PETSCII, `, ` between the parts for plain ASCII.
- **Fixed camera numbers.** `photos::Camera` gains its number; `pick()`
  and CAMERA's list use it instead of the position; `addCamera` sorts by
  it; auto is the lowest free from 2, or from 1 on a board built without
  a camera; a save that clashes is refused.
- **Names one word and unique.** `LINK NAME` accepts spaces today, and a
  two-word name can never be picked by `SNAPSHOT name`. Refuse a space and
  a name another camera has, in LINK NAME and in CONFIG sats.
- **SATS as a core verb** in `cameras.cpp`, registered with the first
  satellite and dropped with the last. From each `photos::Camera` it
  needs, appended: the last picture's time, the levels to filter a caller
  by, a status word, and a staff detail callback that camsat implements
  (CAMERA n calls the same one). Drawn through the paged list, so `SATS n`
  at 40 with four other boards pages instead of scrolling its title off.
  A plugin API change for camsat, which is out of tree: bump
  `UNLEASHED_PLUGIN_API`.
- **The link data the screens read**, from the engine or the radio: rate
  and fallback per peer (today only a count of slow peers), the
  fingerprint, PEERS (names, owner, heard), the channel the satellite was
  last heard on, whether it deep-sleeps and its awake time a picture, its
  firmware version.
- **`markedLine` honouring a newline** as a forced break, for the busy
  answer at 40.
- **camsat (its own repository):** CONFIG camsat gains a read-only row
  saying which satellites its settings reach (`Only the owner's settings
  reach the satellite. This board owns: garden.`), and the busy words
  above.

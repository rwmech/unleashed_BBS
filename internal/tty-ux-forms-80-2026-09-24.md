# tty-ux: the forms at 80 columns

Spec for the 40/80 form layout Rob asked for on 2026-09-24. It replaces the
"Stays" line in `internal/tty-ux-1.1.0-2026-09-23.md` that kept the form a
40-column card at every width. Everything below is measured off
`form.h`/`form.cpp`, the CONFIG tables in `bbs_sysop.cpp`, the account forms
in `bbs_users.cpp`, the plugins' `PluginSetting` tables and `term.cpp`.
Mock-ups were generated from the geometry rules and every line checked
against its width; nothing was drawn by hand.

## Verdict

Fixable in one form file and a sweep of labels. The form already takes a
`Term&` on every call and every position is a constant, so the layout can
become two constant sets chosen by `t.cols()`, with the 40-column set
unchanged byte for byte. The real work is the copy: about a hundred labels get a 20
column version, ten notes get a 78 column version. Static DRAM cost is 128
bytes. A PETSCII-80 page costs 2,422 bytes to draw with today's two cursor
moves a field, inside the 3,072 byte timeline but worth one small change.

## Measured

- Form (form.h:155-159, form.cpp:87-125, gotoXY 1-based): title row 1
  column 1, rule row 2 at 39, fields from row 4, label column 2 width 9,
  box column 12 width 27 with 26 shown, buttons column 12 at last row + 2,
  status column 2 width 38 at last row + 4, textarea column 2 at 4 x 37.
  Same at 80 and 132 today.
- 16 fields: last row 19, buttons 21, status 23, `after()` row 24. Exactly
  a 24-row terminal, at every width.
- Widths come from detect.cpp: ANSI 80x24 or NAWS, plain ASCII 80x24,
  PETSCII-40 40x25, PETSCII-80 80x25. `Term::cols()` is what a form has to
  read; `rowWidth()` (bbs_shell.cpp:488) already does, capped at 132, 40
  when unknown.
- A value longer than 26 shows its tail (form.cpp:165): at 40, announce's
  description reads `oard, up to 120 characters` and its directory URL
  `/unleashedbbs.net/announce`.
- Status line and `fail()` blank 38 (form.cpp:230, 495); `listChoices` packs
  to 39 (form.cpp:590); line mode cuts a shown value at 20 (form.cpp:574).
- The ANSI movement hint "Tab or arrows move, F1 saves, ESC quits" is 39
  characters on a 38 column status line: an ANSI terminal at 40 (NAWS)
  reads `ESC quit`. The PETSCII hint is 37 and fits.
- PETSCII `gotoXY` is HOME + (row-1) cursor-downs + (col-1) cursor-rights,
  one byte each (term.cpp:456). `drawField` does two per field.
- `CfgField` is 20 bytes; `g_cfgPlugin[16]` is the only copy in DRAM
  (bbs_sysop.cpp:1080). `PluginSetting`, `CfgPart`, `UserField` tables are
  all `const` or `constexpr`: flash. `FormField` lives in `Session` 16 times
  (bbs.h:238); a byte there costs 12 x 16.
- Plugin page titles are the plugin's name in lower case
  (bbs_sysop.cpp:1422: `announce`), while core pages and PS_PAGE lists are
  upper case (`BOARD`, `PIXELS`).
- The page list's rows start at column 1 (rowSeg, bbs_shell.cpp:530) under
  a bar whose text starts at column 2.
- `chat` and `serial` declare no settings table, so their labels are the
  raw keys cut at 9 (`color_han`), and only the first 12 keys in the file
  reach the page (bbs_sysop.cpp:1331): with `system.cfg.example`'s 14 chat
  keys, `color_room` and `color_private` are not on it.
- Host build is C++17 (host/Makefile:39): no designated initialisers, so an
  appended struct member is set positionally.

## 1. Geometry

One rule: `formCols = t.cols() >= 80 ? 80 : 40`. Unknown (0) and anything
under 80, including a NAWS of 41 to 79, is the 40 layout. 132 uses the 80
layout: the widest value CONFIG holds is 95 characters and shows 55; a
108 column box is a stripe, and a form is read row by row, not scanned.
At 132 the rule is 79, not 131; the form clears the screen, so nothing
beside it is 131 wide.

| Item | 40 (unchanged) | 80 (and 132) |
|---|---|---|
| Title | row 1, col 1, scramble | same |
| Rule | row 2, 39 | row 2, 79 |
| Label | col 2, width 9 | col 2, width 20 |
| Gap | col 11 | col 22 |
| Box | col 12, width 27 | col 23, width 56 |
| Value shown | 26 | 55 |
| Box ends | col 38 | col 78 |
| Action button | `[ ` + 23 + ` ]` | `[ ` + 52 + ` ]`, summary still 27 max |
| Textarea | col 2, 4 x 37 = 148 | col 2, 2 x 74 = 148 |
| Buttons | col 12, last row + 2 | col 23, last row + 2 |
| Status line | col 2, 38 | col 2, 78 |
| Note max | 38 | 78 |
| `fail()` blank | 38 | 78 |
| Line-mode `[value]` cut | 20 (17 + `...`) | 60 (57 + `...`) |
| `listChoices` width | 39 | 79 |
| 16 fields: last row / buttons / status / after | 19 / 21 / 23 / 24 | 19 / 21 / 23 / 24 |
| Sign-up (9 fields, textarea): buttons / status | 18 / 20 | 16 / 18 |

- Label padding: `%-20.20s` at 80, `%-9.9s` at 40. A field with no wide
  label shows its short one padded to 20.
- Box width is uniform down the page, as now. Sizing boxes to their cap
  gives a ragged right edge on a page whose whole point is a column.
- Textarea keeps its shape (label row, then rows under it at column 2);
  only `kAreaW` and `kAreaRows` change with width. 2 x 74 is exactly
  `BBS_PROFILE_MAX`, so nothing about the stored profile moves.
- `g_cfgSum` stays `[16][28]`: every summary (area name 24, forum name 24,
  page title 24, `sparkle, random`, `10 pixels`) is 27 or under. The button
  pads to 52 with spaces.
- Status hint at 80, ANSI: "Tab or arrows move, Enter is next, Space steps
  a choice, F1 saves, ESC quits" (76). PETSCII: "CRSR or TAB moves, RETURN
  is next, SPACE steps a choice, F1 saves, <- quits" (75).
- Status hint at 40, ANSI: "Tab/arrows move, F1 saves, ESC quits" (36),
  which fixes the cut `ESC quit`. PETSCII's 37 stands.
- Where the geometry lives: `kLabelCol`, `kBoxCol`, `kBoxW`, `kAreaW`,
  `kAreaRows` become functions of `formCols(t)`. Every `Form` method
  already takes `Term& t`, so no state is stored: 0 bytes.

Values that still scroll at 80 (over 55): announce `servers` 90 and
`support`/`interests` 95, Wi-Fi password 64 (masked), announce
description 95 (the plugin's `kDescMax` is 120, `g_cfgBuf` holds 95, so
CONFIG cannot hold what the file may: pre-existing). Everything else on
every page shows whole at 80.

## 6. Plain ASCII line mode

Plain ASCII is 80x24, so it takes the 80 labels and 80 notes with no other
rule. What changes in `linePrompt`/`keyLine`:

- Prompts use the label the owner selected: `Onboard LED GPIO [2]: `,
  `File area 1 [C64 Downloads] open (y/N)? `, `Pixels, by hand [10 pixels]
  open (y/N)? `. Read-only rows: `Handle: quantumrob`.
- The bracketed current value cuts at 60 (57 + `...`) instead of 20.
- `listChoices` packs to 79. The 31 zone names run one or two a line at
  39 and two or three at 79.
- Notes, `status()` and `fail()` print whole lines at 78.
- `Save (Y/n)?` and the Y/N grammar are unchanged.

## 7. PETSCII-80

The 80 layout is chosen by `cols()`, so a C128 (or a soft-80 C64) gets it
without a type test; `isPet()` still picks the hint text and the cursor
codes. Two things are its own.

Bytes per full draw, PETSCII, `gotoXY` as HOME + downs + rights:

| Page | 40, two gotoXY a field (today) | 40, one | 80, two | 80, one |
|---|---|---|---|---|
| 16 rows (announce) | 1,515 | 1,171 | 2,422 | 1,902 |
| Sign-up (9 rows, textarea) | 1,088 | 943 | 1,553 | 1,322 |

- `BBS_TL_BYTES` is 3,072 and `BBS_RX_ROOM` 1,700: the socket is not read
  while more than 1,372 bytes are queued. A 2,422 byte page holds typed
  keys until about 1,050 bytes drain. Nothing is lost, and the buffer is
  not raised for this.
- The change worth making: `drawField` writes the label, then `right(1)`
  into the box, instead of a second `gotoXY` (form.cpp:150, 166). At 80 a
  second `gotoXY` to column 23 on row 19 is 41 bytes; `right(1)` is one.
  It saves 520 bytes on a full page at 80 and 344 at 40, and 2,422 bytes at
  9600 baud is 2.5 s of drawing against 2.0 s.
- Reverse (0x12/0x92), colour bytes and the 35 ms cascade are what they
  are at 40. The box ends at column 78 and the status at 79, so nothing
  reaches the wrap at 80. 25 rows: `after()` at row 24, row 25 spare, as
  at 40.
- `BBS_PROFILE_MAX`'s comment "4 rows of 37 columns on a C64" becomes
  "4 x 37 at 40, 2 x 74 at 80".

## 8. Data

Append, never insert: every table is filled positionally, and C++17 has no
designated initialisers, so a row setting a new member spells the ones
before it (`nullptr` for a note or choices it has none of).

```

    ...
    const char* note     = nullptr;
    const char* wide     = nullptr;   // 20 characters, the label at 80; null = use label
    const char* wideNote = nullptr;   // 78 characters, the note at 80; null = use note
};
struct PluginSetting { // plugin.h:168
```
